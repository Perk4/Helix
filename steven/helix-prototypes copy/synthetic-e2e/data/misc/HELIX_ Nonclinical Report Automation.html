HELIX

Nonclinical Report Automation  ·  Pharma & Contract Research
A tool that learns a report's structure from past approved ones and drafts the next for the scientist to sign. Every number pulled from source data, every gap flagged, nothing guessed.
Learn once  ·  Generate many  ·  Deterministic where it matters
How it works.  A study pathologist uploads the new study's data and protocol, a few past approved reports of the same type, and the blank template. HELIX retrieves section patterns from those reports, then works section by section: deterministic code extracts each value from source data and validates it. The LLM writes prose only around what passed. Every gap becomes a [NEEDS REVIEW] flag. Every number in the final draft links back to its source row. The scientist edits and signs. Nothing is finalised without them.

Problem
  • Authoring a drug safety study report takes a study pathologist 5 to 6 weeks. The bulk of it is manual transcription and cross-checking of study data rather than the scientific judgment only they can provide.
  • Weeks of a scientist's time go to typing, not judgment.
  • One bad number becomes an FDA audit finding.
Solution
  • Learns a report's structure from past approved ones and drafts the next for the scientist to sign.
  • Every number pulled from source data rather than generated, and traceable back to it.
  • Scientist edits and signs. Nothing finalised without them.
5 to 6 weeks today → under 2 min · first draft
For Whom
  • The study pathologist who authors and signs a drug candidate's safety report, at a pharma preclinical group or a contract research lab.
  • Goal: produce a report the FDA will accept. The science is theirs, and every number matches its source exactly.
Input to Output
What goes in
  • A few approved reports of the same study type
  • The new study's data and protocol
  • The blank report template
What comes out
  • A filled first draft: narrative and tables
  • Every number exact to source and traceable
  • [NEEDS REVIEW] flags instead of guesses
Key Tech
  • Section-chunked RAG: retrieves extraction patterns, not raw values
  • Deterministic extraction: code pulls values; LLM never does math
  • Exact string validation: mismatch flags, never hallucinates
  • LangGraph orchestration · React UI with live pipeline status + one-click provenance
  • RAGAS faithfulness eval · target: zero unvalidated numbers
RAG infrastructure: Pattern RAG indexes approved reports by section to retrieve extraction templates · Study data store indexes the new study CSV for deterministic value lookup and exact-match validation · Every value in the draft traces back to a source row.
