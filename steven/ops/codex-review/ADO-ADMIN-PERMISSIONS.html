3. Pipeline permissions

  1. Open Pipelines → Pipelines.
  2. For All pipelines or the root folder, select More actions (…) → Manage security.
  3. Search for steven.espaillat@accenture.com.
  4. Set to Allow: View build pipeline, Create build pipeline, Edit build pipeline, and Queue builds.

Known gap: View, Create, and Queue currently appear inherited. Edit build pipeline is currently not set and must be granted.

4. One-time Classic pipeline setting

  1. Open Project settings → Pipelines → Settings.
  2. Temporarily turn off Disable creation of classic build pipelines.
  3. Notify Steven that creation is enabled.
  4. After Steven confirms that Codex PR Review was created, turn the setting back on.

This is preferred over granting broad Project Administrator access. The server-controlled definition prevents pull-request code from altering the credential-bearing review task.

  2. Open security for the root LLMGenAITitaniumEngineering area path.
  3. For steven.espaillat@accenture.com, set View work items in this node and Edit work items in this node to Allow.
  4. Ensure the permissions inherit to child area paths.

6. Build-service runtime permissions

  1. Return to Project settings → Repositories, select the repository, and open Security.
  2. Search for LLMGenAITitaniumEngineering Build Service (LLMGenAITitaniumEngineering).
  3. Set only Read and Contribute to pull requests to Allow.

The project-scoped System.AccessToken can then read PR data and publish review threads and statuses, but cannot push code.

7. Security settings to retain

Under Project settings → Pipelines → Settings, confirm:

  • Limit job authorization scope to the current project is enabled.
  • Referenced-repository protection remains enabled.
  • Access to secrets from fork builds remains restricted.

8. Credential scopes, if a PAT or OAuth token is used

  • Code: Read & write — vso.code_write
  • Work Items: Read & write — vso.work_write
  • Build: Read & execute — vso.build_execute
  • Project and Team: Read & write — vso.project_write, only if Steven will change the Classic-pipeline setting

Token scopes do not override Azure DevOps security permissions. Store all credentials as secrets and never commit them to the repository.
