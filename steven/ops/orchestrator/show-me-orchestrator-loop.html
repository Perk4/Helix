A resumable ticket burn-down loop

orch run snapshots GitHub, reserves one stable action, launches the configured agent, executes policy-owned verification, and records proof in trusted PR comments. It stops at READY-FOR-MERGE so a human can review and merge, then resumes on the next invocation.

Components

01

GitHubAdapter

Reads repo, issues, PRs, status checks, and trusted collaborator comments through gh. Normalizes them into snapshots.

02

Reconciler + state file

Atomically persists normalized state under an exclusive file lock. Clears a pending action only when its effect is observable.

03

Deterministic planner

Chooses one eligible issue by priority → creation time → number, then computes exactly one action.

04

Run controller

Owns agent launch, bounded retries, CI polling, idempotent GitHub mutations, and the terminal human handoff.

05

Proof recorder

Turns strict result JSON into policy-, SHA-, and stack-bound proof. Finding events fold by stable ID.

06

Ready gate

Requires an open non-draft PR, successful checks, no current P0/P1 findings, current review and test proof, and a valid stack parent.

Exact prompt shape

All four prompt actions use the same wrapper; only target values and the highlighted instruction change.

$pstack:poteto-mode

Execute orchestrator action {kind} for {PR #n | issue #n} in {owner/repo}.
Action ID: {action_id}
Expected head SHA: {sha | none}
Expected stack fingerprint: {fingerprint | none}

{action-specific instruction below}

Work only on this ticket. Preserve unrelated changes. Do not label the PR READY-FOR-MERGE.
Write exactly one JSON object to stdout. Use the supplied action-specific schema and identity values.
Output JSON only. No Markdown. No extra keys.
implement_issueagent prompt
Implement the issue acceptance criteria, run proof tests, push the ticket branch, and open its correctly based PR.

Completion is observed indirectly when an open/merged PR closes the issue.

review_pragent prompt + complete
Invoke $mattpocock-skills:code-review on the current PR head and report every finding with severity and resolution state.

Must return action ID, head SHA, fingerprint, pass/fail, summary, and optional findings; then call orch complete.

patch_pragent prompt
Patch the unresolved review findings only, run focused proof tests, and push the updated head.

Completion is observed through a changed PR head or disappearance of blocking findings.

verify_pragent prompt + complete
Run the trusted repository verification commands and report their exact exit status and evidence.

Must return the same proof result shape as review; findings may be omitted.

Completeness review

Strong: deterministic and resumable

Action IDs derive from action identity; duplicate next, claim, completion, and ready application converge safely.

Strong: stale proof protection

Head SHA and stack fingerprint bind both review and test receipts; parent/head changes invalidate old proof.

Strong: fail-closed merge gate

Missing checks, proof, valid parent, or clean P0/P1 state prevents readiness.

Closed: built-in loop and agent launcher

orch run owns scheduling, process launch, bounded retries, CI polling, reconciliation, and stop behavior.

Closed: finding identity and lifecycle

Finding markers carry stable IDs, head SHA, and stack identity. Later events replace earlier state for the same ID. Old-head findings do not block a new head.

Closed: exact result contracts

Every prompt includes its full JSON shape. Boundary parsing rejects missing keys, extra keys, prose, and mismatched action identity.

Closed: policy-owned verification

The policy names exact argv arrays. The runner verifies a clean checkout at the PR head, executes the commands itself, and binds proof to the policy digest.

Remaining limit: 1,000-item boundary

Multiple open PRs for one issue are rejected. Issue and PR queries now fail closed at 1,000 results, but cursor pagination is still required for larger repositories.
