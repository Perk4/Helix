02

Architectural principles

The constraints that shape component ownership.

Authority

Server-owned truth

FastAPI owns state, validation results, release gates, approvals, and export eligibility. React holds transient view state only.

Safety

Models propose; Python decides

A model can choose an allowlisted check. Deterministic code calculates and assigns the authoritative result.

Traceability

Evidence before narrative

Claims resolve through provenance edges to exact records before report text is assembled.

Human gate

Judgment is explicit

Dispositions and approval roles are separate workflow commands—not implicit model behavior.

Release

Export is a boundary

Artifacts are generated only after readiness, then exact bytes and hashes are stored.

Experiment

Agent output is isolated

A Codex draft candidate can be reviewed but cannot enter the principal report or export path.

06

Domain and persistence model

One mutable aggregate plus independent records for history, attempts, and frozen bytes.

Aggregate root

StudyEvidencePackage ├── study ├── manifest[] ├── records{domain → record[]} ├── claims[] ├── provenance_edges[] ├── validation_results[] ├── report_sections[] ├── review_dispositions[] ├── approvals[] ├── gate_decisions[] ├── export_artifacts[] └── events[]

Command transaction

Relational storage around the aggregate

Persistence tension

The coarse aggregate is appropriate for fast prototype evolution, but whole-package rewrites will become expensive at scale. Events are duplicated inside the package and in audit_events; no reconciliation invariant currently prevents divergence. The row version increments but is not an optimistic update predicate.

10

Security, compliance, and governance

Useful prototype controls exist, but they are not a compliance determination.

Implemented

Current safeguards

  • Strict Pydantic models reject unknown fields.
  • PostgreSQL command paths use transactions and row locks.
  • Idempotency keys constrain exports, events, and section runs.
  • Codex runs in a read-only sandbox with a scoped envelope.
  • Envelope and candidate JSON are schema validated.
  • Artifact bytes are SHA-256 verified before download.
  • Release state is derived on the server.
  • Synthetic labeling is checked and preserved.
Gap

Not implemented

  • Authentication, authorization, tenants, or study ACLs.
  • Authenticated identities or electronic signatures.
  • Approval binding to exact report/artifact hashes.
  • General approval invalidation after governed changes.
  • Secrets management and model-egress governance.
  • Rate limits, application timeout, or agent cancellation.
  • Migration and backup/restore frameworks.
  • Formal GLP, Part 11, SEND, eCTD, privacy, or security qualification.

Risks and recommended roadmap

Sequence fixes by operability, workflow integrity, evolution, then formal readiness.

Priority 0

Make the documented deployment runnable

  • Package skills, contracts, and package definitions in the backend image.
  • Add a Compose smoke test against /workspace, not only /health.
  • Declare one authoritative repository, branch, and commit.
Priority 1

Protect workflow integrity

  • Add authentication and role-based authorization.
  • Bind approvals to package/report hashes and invalidate on change.
  • Use authenticated principal identities rather than request labels.
  • Enforce skill qualification and add agent timeout/cancellation/observability.
Priority 2

Support controlled evolution

  • Add Alembic migrations and compatibility policy.
  • Choose one audit authority or continuously reconcile both.
  • Replace hard-coded IDs with governed registries and executors.
  • Add explicit concurrency tests and optimistic version checks if needed.
  • Split large immutable records from frequently changing package state as load grows.
Priority 3

Prepare for production and regulatory assessment

  • Design governed ingestion and authorization.
  • Establish model endpoint, data classification, retention, redaction, and audit policy.
  • Integrate qualified terminology and SEND validation tooling.
  • Replace illustrative artifact generators with validated publishing/submission pipelines.
  • Perform formal GLP, Part 11, privacy, security, and records-management assessments.
